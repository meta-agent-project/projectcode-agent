# projectcode 규칙

모든 projectcode 스킬은 시작할 때 이 파일을 읽는다.

## 목적

- 강의용 코드를 만든다. 프로덕션 코드가 아니다
- 그 장에서 배울 것만 담는다
- 원고와 책의 재료를 남긴다: 커밋, 계획, 캡처, 도식
- 다음 강의도 같은 방식으로 만든다

## 폴더

```
.projectcode/
  roadmap.md          목차와 장 상태
  contract.md         기술, 실행 · 테스트 · 캡처 방법
  chapters/<장>/
    spec.md
    mockup.html
    plan.md
    tasks.md
    captures/         화면 PNG, API 결과 JSON
    diagrams/         흐름, ERD, 폴더 구조도
    fixes/            fix 때 만든 그 장 시점 patch
  wiki/               프로젝트 전체 보기
tests/                행동 테스트
```

코드는 .projectcode/ 밖에 둔다.

## 장

- 장 ID는 영문 소문자 이름이다. 예: signup-form
- 장 번호는 roadmap 순서로만 정한다. 커밋과 폴더에는 ID만 쓴다
- 첫 장은 project-setup이다. 프로젝트 뼈대, 도구, 공통 CSS, 테스트 실행기를 넣는다
- 장 종류는 기능, 리팩터 두 가지다
- 장의 문서와 자료는 그 장이 끝난 시점을 보여준다. 뒤 장은 앞 장 문서를 고치지 않는다
- 완료된 장을 고치는 것은 projectcode-fix만 한다

## 장 상태

roadmap.md에 글자로 쓴다.

| 상태 | 뜻 |
|---|---|
| 대기 | 아직 시작하지 않음 |
| 진행 중 | 지금 만드는 장. 하나뿐이다 |
| 멈춤 | fix 때문에 잠시 멈춘 장 |
| 완료 | tasks.md가 모두 체크됨 |
| 수정 중 | fix로 다시 연 장 |

## 커밋

- 기본 브랜치에 커밋한다
- 제목은 [장 ID] 뒤에 짧은 한국어로 쓴다. 이모지와 기호를 넣지 않는다
- 본문에 꼬리표를 쓴다

```
[signup-form] 입력값을 state로 기억하기

Chapter: signup-form
Kind: feature
Task: T2
Why: 입력한 값을 다음 단계에서 서버로 보내려면 기억해 둬야 한다
```

| 꼬리표 | 언제 쓰나 |
|---|---|
| Chapter | 장 커밋에 항상 |
| Kind | 항상. docs, test, feature, refactor, fix 중 하나 |
| Task | task 하나를 구현한 커밋 |
| Why | feature, refactor, fix 커밋 |
| Touches | 완료된 다른 장의 파일을 바꿀 때. 그 장 ID |
| Fixes | fix 커밋. 고친 코드를 처음 만든 task 커밋 해시 |

장에 속하지 않는 커밋(초기화, roadmap, contract)은 제목을 [projectcode]로 시작하고 Kind: docs만 쓴다.

장 하나는 트랜잭션처럼 묶는다.

| 커밋 | 언제 |
|---|---|
| [장] 시작 | plan 승인 뒤. spec, mockup, plan, tasks를 담는다 |
| [장] 완료 | tasks.md가 모두 체크된 뒤. 태그 done/<장>을 단다 |
| [장] 수정 시작 | fix로 장을 다시 열 때 |
| [장] 수정 완료 | fix가 끝날 때 |

## 승인

- spec, mockup, plan에서 사람의 승인을 받는다
- fix는 수정 계획에서 승인을 받는다
- 승인 뒤에는 이어서 진행한다. 넘침이 나오면 멈추고 묻는다

## 넘침

코드가 선언보다 많은 것이다. 세 가지만 비교한다.

| 무엇 | 비교 대상 |
|---|---|
| 동작 | spec.md의 할 일 S번호 |
| 파일 | plan.md의 파일 목록 |
| 라이브러리 | contract.md와 plan.md |

개념이 새것인지는 판단하지 않는다. 그것은 roadmap에서 사람이 정한다.

## 문서 쓰는 법

- 한국어로 짧게 쓴다. 한 줄에 하나만 쓴다
- 기호는 #, -, 번호만 쓴다. 표는 써도 된다. 코드 블록은 예시에만 쓴다
- 굵은 글씨(**), 링크, 이모지를 쓰지 않는다
- 단어나 파일 이름을 백틱(`)으로 감싸지 않는다. 그냥 쓴다
- 최신 내용만 쓴다. 이력은 커밋에 남는다

## 코드 쓰는 법

- 학생에게 읽어 주는 코드다. 읽기 쉽게 쓴다
- 학생이 지금까지 배운 것으로 위에서 아래로 읽히는 가장 단순한 코드로 쓴다
- 나누는 이유를 설명할 수 없으면 파일이나 함수를 나누지 않는다
- 파일과 함수를 어떻게 나눌지는 plan.md에서 정하고 사용자가 승인한다
- lint는 포맷만 맞춘다. 줄 수 같은 길이 규칙은 두지 않는다
- plan.md에 있는 것만 쓴다. 더 필요하면 멈추고 묻는다
