# projectcode-codealong

학생은 쳤다가 고치는 코드를 보지 않는다. 처음부터 고친 코드를 친다.
그래서 main 이력을 그대로 읽지 않고, 고침을 녹인 lecture 브랜치를 쌓아 그것을 읽는다.

## 대상

| 대상 | 쓰는 파일 |
|---|---|
| 처음부터 따라 치는 학생 | 따라치기 처음부터 |
| 앞 장은 할 줄 알고 뒤를 배우려는 학생 | 합류 지점 문서를 복붙하고 따라치기의 다음 장부터 |
| 폐쇄망 기업 강의 | 결과 폴더를 통째로 가져간다. 외부 링크와 다운로드가 없다 |

## 파일

```
.projectcode/code/
  따라치기.md, 따라치기.html     장마다 단계마다 코드
  그림완성.md, 그림완성.html     합류 지점 하나마다 하나. 이름은 roadmap에서 정한다
```

- MD와 HTML은 같은 내용이다. HTML은 브라우저로 연다
- HTML은 파일 하나로 끝난다. 외부 CSS, 글꼴, 스크립트가 없다
- HTML 코드 색은 GitHub Light 테마다. 만들 때 shiki로 미리 칠해 넣는다
- shiki가 없으면 이 스킬 폴더에서 npm install을 한 번 한다
- 사진은 넣지 않는다
- lecture 브랜치는 강사용이다. 학생에게 주지 않는다
- 학생 코드 폴더만 담는다. contract.md 폴더 표의 학생 코드 폴더다
- 결과 폴더는 매번 처음부터 다시 쓴다

## 문서 모양

| 자리 | 모양 |
|---|---|
| 제목 | # 강의 이름 따라치기 (roadmap 강의 이름) |
| 준비 | contract.md 실행의 서버, 프론트 줄과 브라우저 주소. 두 문서 모두 |
| 장 제목 | ## 4 component-split 겹치는 화면을 컴포넌트로 |
| 단계 제목 | ### 4-1 글 카드를 컴포넌트로 빼고 props로 넘기기 |
| 왜, 실행하면 | 넣지 않는다 |
| 시작 키트 복사 | lecture 첫 커밋이다. 칠 코드가 없어 넣지 않는다 |

파일 표시는 네 가지다.

| 표시 | 뜻 | MD | HTML |
|---|---|---|---|
| 삭제할 파일 | 지운다 | 경로 목록 | 경로 목록 |
| 새 파일 | 새로 만든다 | diff 블록, 모든 줄이 + | + 기호와 초록 바탕, 코드 색 |
| 수정 파일 | 있는 코드를 부분부분 고친다 | diff 블록 | + 줄 초록, - 줄 빨강 바탕, 코드 색 |
| 덮어쓸 파일 | 있는 코드를 통째로 바꾼다 | 코드 블록 | 코드 색 |

HTML 파일마다 복사 아이콘이 하나 있다. 누르면 고친 뒤의 완성된 코드가 복사된다.
- - 줄은 빼고 + 줄과 그대로인 줄을 기호 없이 복사한다
- diff 구간이 여럿이면 구간 사이에 빈 줄 하나를 둔다
- 새 파일과 덮어쓸 파일은 코드 전체가 복사된다

- 단계 diff에서 지운 파일은 삭제할 파일, 더한 파일은 새 파일, 바뀐 파일은 수정 파일이다
- 합류 지점 문서의 통째로 부분은 삭제할 파일, 새 파일(시작 키트에 없던 것), 덮어쓸 파일(있던 것)이다

## 합류 지점

roadmap.md에 적는다.

```
## 합류 지점
- component-split: 그림완성, 통째로 screens
- 따라치기: 처음부터
```

- 앞은 합류 장, 뒤는 파일 이름이다
- 통째로 장까지는 파일을 통째로 주고, 그 뒤 합류 장까지는 단계 diff로 준다
- 통째로를 빼면 합류 장 끝까지 통째로 준다
- 따라치기는 처음부터 또는 board-list부터처럼 시작 장을 적는다. 중간부터면 앞 장은 빼고 합류 지점 문서로 하라는 한 줄을 쓴다
- 여러 개를 둘 수 있다. 강의하는 곳마다 고른다
- 완료된 장만 고를 수 있다

## 따라치기 제목

고침을 녹이면 단계 코드가 바뀌어 원래 커밋 제목과 어긋날 수 있다.
사용자가 정한 제목은 roadmap.md에 적고, 엔진은 커밋 제목보다 이 값을 먼저 쓴다.

```
## 따라치기 제목
- join T1: 회원가입 input 입력 값을 상태로 저장하기
```

## 고침과 진도

뒤 단계가 앞 단계 코드를 바꾸는 경우는 두 가지다. 커밋 꼬리표로 가른다.

| 종류 | 꼬리표 | lecture에서 |
|---|---|---|
| 고침 | Kind: fix와 Fixes: <대상 커밋> | 대상 단계로 녹인다. fix 단계는 없앤다 |
| 진도 | Kind: feature나 refactor와 Touches | 그 단계에 그대로 둔다. 학생이 바꿔 보는 수업이다 |

- 두 장에 걸친 fix는 둘째 장의 Fixes가 본문에 있다. 커밋 메시지 안의 Fixes: 줄을 모두 읽는다
- 장 안 수렴이 더한 고칠 task(근거가 넘침, 빠짐, 어긋남)는 Kind가 feature라 꼬리표로 가를 수 없다. 목록으로 보여주고 녹일지 사용자에게 묻는다

## 순서

1. 단계 고르기
   main에서 Chapter와 Task 꼬리표가 있고 Kind가 feature나 refactor인 커밋을 이력 순서로 고른다.
   - 학생 코드 폴더를 바꾸지 않는 커밋은 뺀다
   - 완료된 장까지만 담는다. 진행 중이거나 마무리 중인 장은 넣지 않는다
   - Kind fix 커밋마다 Fixes 대상을 모은다. 녹일 구간은 가장 앞 대상 커밋부터 fix 커밋 바로 앞까지다

2. lecture 브랜치 쌓기
   서브에이전트가 임시 worktree에서 한다. 메인 작업 폴더는 건드리지 않는다.
   - 첫 단계 커밋에서 lecture 브랜치를 새로 시작한다. 첫 단계는 시작 키트를 복사한 커밋이다
   - 단계마다 학생 코드 폴더를 main의 그 단계 커밋 상태로 맞춘다
   - 단계도 고침도 아닌 커밋이 더한 파일(예 API 문서)은 뺀다
   - 녹일 구간 안의 단계면 그 fix와 같은 수정을 얹는다. 그 장의 fixes/ patch가 붙으면 붙이고, 안 붙으면 손으로 같은 수정을 한다
   - 바뀐 것이 없는 단계는 커밋하지 않는다. 녹여서 사라진 단계다
   - 커밋 메시지는 원래 제목에 꼬리표 셋이다

```
[board-save] 글쓰기 입력값을 객체로 기억하기

Chapter: board-save
Task: T1
Source: 5926288 4c0da83
```

   Source는 main의 원래 커밋과 녹인 fix 커밋이다.
   이미 lecture 브랜치가 있으면 새 fix의 가장 앞 대상 단계 바로 전까지는 그대로 두고, 그 뒤만 다시 쌓는다.

3. 확인
   - 장마다 마지막 lecture 커밋의 학생 코드가 done/<장> 태그에 그 장 fixes/ patch를 모두 붙인 것과 같다
   - patch가 없는 장이 녹일 구간 안에 있으면, 다른 곳이 그 fix가 고친 파일뿐인지 본다
   - 가장 마지막 lecture 커밋의 학생 코드가 마지막 완료 장의 끝 코드와 같다
   - 다르면 멈추고 다른 파일을 보여준다

4. 인터뷰
   AskUserQuestion으로 한 번에 하나씩 묻는다.
   - 합류 지점 줄과 따라치기 시작 장을 보여 주고 이대로 할지 묻는다. 몇 장까지 통째로, 어디부터 diff, 따라치기를 어디부터 둘지다. 바꾸면 roadmap에 적는다
   - 고침을 녹인 단계 중 그 fix가 고친 파일을 직접 바꾸는 단계를 고른다. 단계마다 원래 제목과 녹인 뒤 코드를 보여 주고 제목이 맞는지 묻는다. 바꾸면 roadmap 따라치기 제목에 적는다

5. 뽑기
   메인 저장소 루트에서 실행한다.
   node .claude/skills/projectcode-codealong/codealong.mjs --branch lecture --out .projectcode/code

6. 점검
   - 합류 지점 MD대로 시작 키트에 적용한 결과가 합류 장 끝 lecture 커밋과 같다
   - 따라치기 MD대로 시작 지점에 적용한 결과가 마지막 lecture 커밋과 같다
   - HTML 복사 글자가 MD 블록에서 - 줄을 빼고 기호를 뗀 것과 같다
   - 따라치기에 fix 단계 제목이 남지 않았다
   - HTML을 브라우저로 한 번 열어 색과 복사 버튼을 본다

7. 커밋
   결과 폴더와 roadmap.md에서 이 스킬이 적은 줄만 커밋한다. 다른 세션이 바꾼 줄은 넣지 않는다.
   제목: [projectcode] 따라치기 갱신
   본문: Kind: docs
   lecture 브랜치는 사용자가 원할 때만 원격에 올린다. 다시 쌓으면 강제 푸시가 된다.

## 언제

- 사용자가 요청할 때
- 장이 완료되거나 fix가 끝난 뒤 따라치기를 새로 뽑고 싶을 때
