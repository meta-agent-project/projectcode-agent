# projectcode-spec

장 하나가 무엇을 하는지 사람이 읽고 판단할 수 있게 쓴다. 어떻게 만들지는 plan이 쓴다.

## 언제

- roadmap에서 상태가 대기인 첫 장을 시작할 때
- 진행 중인 장의 spec을 바꿀 때
- 완료된 장은 여기서 고치지 않는다. projectcode-fix를 쓰라고 알린다

## 순서

1. 확인
   다른 장이 진행 중이면 멈추고 알린다. 진행 중인 장은 하나뿐이다.
   roadmap.md에서 이 장의 상태를 진행 중으로 바꾼다.

2. 읽기
   roadmap.md에서 이 장의 배울 것, 선수 지식, 미룬 것, 하지 않는 것을 읽는다.
   contract.md와 바로 앞 장의 spec.md를 읽는다.

3. 초안 쓰기
   아래 형식대로 쓴다.
   - 할 일은 S1부터 번호를 붙인다. 한 줄에 동작 하나다
   - 할 일 하나는 행동 테스트 하나로 확인할 수 있어야 한다
   - 화면이 있으면 글자로 그린다. 화면이 없으면 요청과 응답 예시를 쓴다
   - 흐름은 화살표로 한 줄에 쓴다
   - 라이브러리, 함수, 파일 이름은 쓰지 않는다

4. 범위 묻기 (최대 5개)
   이 장을 만들다 보면 넣고 싶어지는 것을 찾는다. 예: 입력 검사, 오류 메시지, 로딩 표시
   하나씩 묻는다. 선택지는 세 개다.
   - 이 장에서 만든다: 할 일에 넣는다
   - 미룬다: roadmap의 미룬 것과 spec의 안 하는 것에 적는다
   - 안 만든다: roadmap의 하지 않는 것과 spec의 안 하는 것에 적는다
   추천은 roadmap의 배울 것을 기준으로 한다. 배울 것이 아니면 미룸이나 안 만듦을 추천한다.

5. 크기 점검
   아래 둘 중 하나라도 해당하면 장을 나눌지 묻는다.
   - 이 장의 배울 것에 이어지지 않는 할 일이 있다
   - 흐름이 한 줄로 이어지지 않고 따로 도는 흐름이 둘 이상이다
   나누면 roadmap.md에 장을 하나 더하고, 이 장의 할 일만 남긴다.
   새 장은 이 장 바로 뒤에 대기 상태로 넣는다. 그 장의 spec은 차례가 오면 따로 쓴다.
   나누기는 spec 단계에서만 한다. plan 승인 뒤에는 나누지 않는다.

6. 보여주고 승인받기
   spec 전체를 채팅창에 보여준다.
   승인을 받으면 .projectcode/chapters/<장>/spec.md에 저장한다. 승인 전에는 저장하지 않는다.
   커밋은 하지 않는다. task 승인 뒤 [장] 시작 커밋에 함께 들어간다.

7. 다음
   새 화면이 있으면 projectcode-mockup, 없으면 projectcode-plan이라고 알린다.

## 진행 중인 장의 spec을 바꿀 때

- spec.md를 최신 내용으로 고친다. 낡은 글은 지운다
- plan.md나 tasks.md가 이미 있으면 바뀐 할 일에 맞춰 함께 고치고 다시 승인받는다
- 이미 구현한 task가 바뀌면 tasks.md에 고칠 task를 새로 더한다

## spec.md 형식 (기능 장)

```
# signup-form 회원가입 폼

종류: 기능
배울 것: 컴포넌트, JSX, useState

## 할 일
- S1 회원가입 화면을 띄운다
- S2 아이디와 비밀번호를 입력하면 화면이 값을 기억한다
- S3 가입하기를 누르면 입력값을 콘솔에 보여준다

## 화면
+------------------------------+
| 회원가입                      |
| 아이디   : [____________]     |
| 비밀번호 : [____________]     |
|              [ 가입하기 ]     |
+------------------------------+

## 흐름
입력 -> 값 기억 -> 가입하기 클릭 -> 콘솔에 아이디와 비밀번호

## 안 하는 것
- 입력 검사: 미룸
- 서버로 보내기: signup-connect 장
```

## spec.md 형식 (화면이 없는 장)

```
# signup-api 회원가입 API

종류: 기능
배울 것: Express 라우트, SQLite 저장

## 할 일
- S1 아이디와 비밀번호를 받아 사용자로 저장한다
- S2 저장하면 성공 응답을 돌려준다

## 요청과 응답
POST /api/signup
요청: { "id": "kim", "password": "1234" }
응답: { "ok": true }

## 흐름
요청 -> 사용자 저장 -> 성공 응답

## 안 하는 것
- 같은 아이디 막기: 미룸
- 비밀번호 암호화: 안 만듦
```

## spec.md 형식 (리팩터 장)

```
# router-cleanup 경로 정리

종류: 리팩터
배울 것: 경로 상수, 중첩 라우트

## 할 일
- S1 화면 주소를 한 곳에 모은다
- S2 로그인과 회원가입 화면을 하나의 묶음 경로 아래로 옮긴다

## 그대로인 것
- 모든 화면의 동작과 모습은 바뀌지 않는다
```
