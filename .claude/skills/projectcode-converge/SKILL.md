# projectcode-converge

장의 코드가 선언과 맞는지 마지막으로 확인한다.
implement는 커밋마다 검사했고, 여기서는 장 전체를 새 눈으로 다시 본다.

## 네 가지 분류

| 분류 | 뜻 | 비교 |
|---|---|---|
| 빠짐 | spec의 할 일이 코드에 없다 | 할 일 S번호마다 코드와 테스트 |
| 어긋남 | 코드가 spec과 다르게 동작한다 | 할 일 글과 실제 동작 |
| 넘침 | 코드가 선언보다 많다 | 동작은 spec 할 일, 파일은 plan 파일 목록, 라이브러리는 contract와 plan |
| 순서 어긋남 | task 커밋이 자기 근거 밖의 코드를 담았다 | T 커밋마다 그 task의 근거 S번호 |

- 테스트가 통과한다는 것만으로 됐다고 보지 않는다. 테스트가 그 할 일을 정말 확인하는지 본다
- 개념이 새것인지는 판단하지 않는다

## 순서

1. 범위 정하기
   이 장의 [장] 테스트 작성 커밋부터 지금까지 Chapter 꼬리표가 이 장인 커밋을 찾는다.

2. 검사
   새 서브에이전트에게 맡긴다. 구현 과정의 대화는 넘기지 않는다.
   넘길 것: spec.md, plan.md, tasks.md, contract.md, 찾은 커밋 목록과 바뀐 내용
   돌려받을 것: 항목마다 분류, 위치(파일과 줄), 근거(S번호나 plan 줄), 이유 한 줄
   확실하지 않은 항목은 확인 필요로 돌려받는다.

3. 사용자에게 묻기

   | 분류 | 묻는 것 |
   |---|---|
   | 빠짐 | 묻지 않는다. 고칠 task로 더한다 |
   | 어긋남 | spec이 맞나, 코드가 맞나 |
   | 넘침 | 지울까, spec과 plan에 올릴까, 미룰까 |
   | 순서 어긋남 | 묻지 않는다. 아래대로 커밋을 다시 나눈다 |

   spec과 plan은 사용자가 허락할 때만 고친다.

4. 결과에 따라
   고칠 것이 없으면
   - tasks.md의 수렴 점검을 체크한다
   - 다음은 projectcode-capture로 사진사를 보낸다고 알린다

   고칠 것이 있으면
   - tasks.md의 수렴 점검 위에 고칠 task를 더한다. 형식은 다른 task와 같다
   - 테스트가 그 할 일을 확인하지 못해서 생긴 빠짐이나 어긋남이면, 고칠 task 앞에 테스트 보강을 더한다
     테스트 보강은 테스트를 먼저 고치고 실패를 확인한 뒤 [장] 테스트 보강으로 커밋한다. Kind: test
   - 다음은 projectcode-implement라고 알린다. implement가 끝나면 다시 여기로 온다

   세 번 돌았는데도 남으면
   - 더 더하지 않고 멈춘다. 남은 항목을 보여주고 어떻게 할지 묻는다

## 커밋 다시 나누기

순서 어긋남은 원고와 커밋이 맞지 않게 만든다. 그래서 항상 고친다.
범위는 이 장의 아직 완료되지 않은 커밋뿐이다. fix 중이면 이번 fix의 커밋뿐이다.

1. 지금 위치를 백업 브랜치 backup/<장>으로 남긴다
2. 어긋난 첫 T 커밋 바로 앞으로 돌아간다
3. 그 task부터 차례로 다시 커밋한다
   - 코드는 백업의 마지막 코드를 기준으로, 그 task의 근거 S번호만큼만 넣는다
   - 제목과 꼬리표는 원래 커밋 그대로 쓴다
   - implement의 커밋 전 검사를 그대로 한다. 사진은 아직 없으므로 찍지 않는다
4. 마지막 코드가 백업과 같은지 확인한다. 학생 코드와 tests/에 차이가 없어야 한다
   다르면 멈추고 알린다. 백업 브랜치는 남겨 둔다
5. 원격에 올렸으면 git push --force-with-lease로 올린다
6. 백업 브랜치를 지운다

## 알리는 형식

```
signup-form 수렴 점검 (1회차)
빠짐 0, 어긋남 0, 넘침 1, 순서 어긋남 1
- 넘침: src/SignupForm.jsx 12줄 input에 required가 있다. 입력 검사는 미룬 것이다
  지울까요, spec과 plan에 올릴까요, 미룰까요?
- 순서 어긋남: T1 커밋에 S2의 코드(useState 2개, onChange)가 들어 있다
  T1부터 커밋을 다시 나눕니다
```

## 고칠 task 예시

```
- [ ] T4 아이디 칸의 required 지우기
  - 근거: 넘침. 입력 검사는 미룸
  - 파일: src/SignupForm.jsx
  - 실행하면: 빈 칸으로 가입하기를 눌러도 콘솔에 보여준다
  - Why: 입력 검사는 뒤 장에서 배운다
```
